# Wiz VSCode Extension v1.4.2 Release Notes

> March 5, 2026

---

## Highlights

**v1.4.2** fixes an intermittent caching issue in the **TODO Viewer** and **Memo Viewer** — when `todo.md` or `memo.md` was modified externally (by git, Copilot Chat, terminal, etc.), the Webview could display stale cached content. This release introduces `FileSystemWatcher` for external change detection and a disk-first read strategy.

---

## Bug Fixes

### TODO/Memo Viewer Cache Sync
The TODO Viewer and Memo Viewer Webviews could intermittently display outdated content when `todo.md` or `memo.md` was modified by external processes.

- **Root Cause 1**: `loadTodoContent()` / `loadMemoContent()` unconditionally used the VS Code text buffer (`textDocuments`) — if the buffer hadn't been updated yet by VS Code, stale cached content was returned
- **Root Cause 2**: `onDidChangeTextDocument` / `onDidSaveTextDocument` only fire for documents open in VS Code editors — changes from git, Copilot Chat, or terminal writes were not detected
- **Fix**:
  - **FileSystemWatcher reintroduced**: `vscode.workspace.createFileSystemWatcher` monitors the target file for `onDidChange`, `onDidCreate`, `onDidDelete` events from external processes
  - **Disk-first read**: New `loadTodoContentFromDisk()` / `loadMemoContentFromDisk()` methods bypass VS Code buffer cache and always read from disk
  - **Buffer condition tightened**: `loadTodoContent()` / `loadMemoContent()` now only use the VS Code buffer when the document is `isDirty` (has unsaved edits); otherwise falls back to disk read
  - **Tab switch refresh**: `onDidChangeViewState` handler now uses disk-first read for accurate content on tab restore
  - **Loop prevention**: `_isSaving` flag and 300ms debounce maintained to prevent save → watcher → refresh loops
